## 你只需配置一次

1. 使用仓库 `simple-happy-802/vEMDestripe`，将演示文件放在 `main` 分支；如仓库尚未创建，请先创建公开仓库。
2. 将本地 `vEMDestripe` 文件夹**里面的内容**上传到仓库根目录。根目录应直接出现 `README.md`、`infer.py`、`colab/`、`vemdestripe/` 和 `checkpoints/`，不要再多套一层 `vEMDestripe/`。
3. 确认论文权重 `checkpoints/vemdestripe_seed42/best.pth` 已上传。不要把整个原始数据集、运行日志、临时文件上传到代码仓库。
4. Notebook 已设置 `GITHUB_OWNER = "simple-happy-802"`、仓库 `vEMDestripe`、分支 `main` 和 Release 标签 `demo-v1`；中英文 README 的 Colab 按钮也已配置好，无需再替换用户名。
5. 创建一个标签为 `demo-v1` 的 GitHub Release，将已经生成的 `release_assets/vemdestripe_bumbarger_demo_z0777_z0808.zip` 上传为 Release 附件。文件约 **74.4 MiB**，保留文件名，不要将解压后的图片逐张上传到代码仓库。
6. 发布 Release 后，点击 README 的 **Open in Colab**，自己从头运行一次。确认下载、两种现场处理、对比视图和指标均完成后，再把这个链接放进论文。

## 别人怎样使用

1. 点击 **Open in Colab** 并连接运行时。
2. 选择 **Runtime → Change runtime type → T4 GPU**，然后选择 **Runtime → Run all**。
3. 等待数据下载和处理完成。vEMDestripe 使用发布权重进行推理；官方 EMISAC 使用 CPU 优化，是较慢的现场运行步骤，启用 GPU 不会让它变成 GPU 算法。
4. 通过滑块查看 XY、XZ、YZ 图像和沿 Z 轴的亮度曲线，查看重新计算的 `demo_window_metrics.csv`。
5. 最后一个导出单元格会生成结果 ZIP，点击 **Download results ZIP** 按钮即可下载；也可从 Colab 左侧“文件”面板下载。ZIP 包含现场输出、明确标记的备用输出和指标 CSV。

EMISAC 可能打印 `Bad rank filter performance is expected`：这是官方平滑步骤的速度提醒，不等于运行失败。以任务成功结束、32 张输出完整且指标单元格正常完成为准。Colab 断开后临时结果会丢失，请及时下载 ZIP。

## 演示范围必须说清楚

- 数据固定为 Bumbarger13 中的 **32 张 1024×1024 切片**，不是完整体数据；现场指标不能冒充论文 200 张评估窗口的结果。
- **vEMDestripe**：优先现场运行论文发布权重；没有 GPU 时可使用明确标记的备用输出。
- **EMISAC**：现场获取并运行作者官方仓库的固定 commit，仅添加公开的 Python 3/依赖兼容修改，不使用本地 GPU 改写版结果。
- **FECNet、SSCOR**：展示已经冻结的论文实验输出，并提供作者官方源码查看。它们**不是在此 Notebook 中现场重训**。目前缺少对应 Bumbarger 实验的 FECNet 专用权重；SSCOR 对测试体数据进行专门训练，耗时较长。不能把该演示描述为“四种方法全部现场重跑”。
- Bumbarger13 没有逐切片配对的干净标签，Notebook 不报告 PSNR/SSIM；参考切片也不是配对真值。

第三方代码和数据来源见 [THIRD_PARTY_METHODS.md](THIRD_PARTY_METHODS.md) 与 [DATA_LICENSE.md](DATA_LICENSE.md)。
